# Автоматизация работы с запросами пользователей в службу поддержки с помощью ИИ

**Методические материалы для участников хакатона «Tender Hack — Нижний Новгород»**  
САНКТ-ПЕТЕРБУРГ

---

## Ключевые задачи хакатона

- Изучить предоставленные организаторами данные.
- Структурировать неформализованную базу знаний на основе предоставленных методичек, инструкций и других источников.
- Разработать сервис для автоматического консультирования пользователей, в частности, по типовым и часто задаваемым вопросам.
  - При этом если в базе знаний нет ответа на вопрос, система должна уведомить пользователя об отсутствии информации и предложить обратиться к оператору.
- Реализовать механизм распознавания нецензурной лексики для автоматического завершения таких обращений и информированием пользователя о нарушении правил общения.
- Наделить систему способностью идентифицировать обращения для сотрудников различных линий поддержки.
- Реализовать методику оценивания результатов работы технических специалистов, а также качества донесения информации до пользователей на основе анализа положительных и отрицательных отзывов с формированием содержательного заключения для выявления системных проблем.
- Обеспечить удобный и интуитивно понятный пользовательский веб-интерфейс.
- Протестировать систему на реальных кейсах.
- Предусмотреть возможность масштабирования системы.
- Продемонстрировать работоспособность проекта.
- Презентовать проект. Разработать схему реализации в нотации BPMN.

---

## Пользователь сервиса должен иметь возможность

1. Вводить текстовый вопрос на естественном языке (в том числе с опечатками) и получать релевантный ответ с использованием информации из структурированной базы знаний, сформированной на основе предоставленных методичек и других источников.
2. Получать уведомление, если в базе знаний отсутствует информация по запросу пользователя, с предложением обратиться к оператору поддержки.
3. Получать автоматическое уведомление о завершении обращения и информированием пользователя о нарушении правил общения в случае обнаружения в сообщении нецензурной лексики.
4. Видеть, кому адресовано сообщение (специалисту различных линий поддержки или иному лицу), а также отслеживать статус обработки обращений в интерфейсе диалога или личном кабинете.
5. Оценивать работу технических специалистов и качество полученной информации после завершения обращения, оставляя положительный или отрицательный отзыв, а также формировать содержательное заключение по результатам анализа обращений для выявления системных проблем.

---

## Ограничения

1. Решение должно работать на операционной системе семейства Linux и предоставлять веб-интерфейс.
2. В рамках хакатона ваша интеллектуальная система поиска должна функционировать **ИСКЛЮЧИТЕЛЬНО** на серверах, контролируемых вашей командой, без привлечения сторонних ресурсов. Это означает полный запрет на использование **ЛЮБЫХ** внешних API, включая:
   - API сторонних поисковых движков: Яндекс.Поиск, Google Search API, Bing Search API и аналогичные;
   - внешние API больших языковых моделей (LLM): OpenAI GPT, Google Gemini, Anthropic Claude и другие подобные сервисы.
3. Запрещено использовать low-code и no-code платформы.
4. Разрешено использовать любые открытые ML-модели и нейросети, но выбор должен быть рациональным и соразмерным задачам и ресурсам. Предпочтение будет отдаваться легковесным решениям с высокой скоростью инференса при ограниченных вычислительных мощностях. Необоснованное применение «тяжёлых» моделей будет считаться нерациональным и может снизить итоговую оценку.

## Этапы защиты

### Этап 1

Защита проектов (презентация до 5 минут со схемой реализации в нотации BPMN). Параллельно второй участник команды демонстрирует реальные кейсы. Максимальное количество баллов по критериям — **100**.

### Этап 2

Отправка ссылок на репозитории (или в архиве) с кодом и визуальной частью. Защита топ-5 решений (презентация до 10 минут со схемой реализации в нотации BPMN, затем 10 минут на вопросы жюри). Максимальное количество баллов по критериям — **100**. Баллы суммируются с баллами первого этапа.

---

## Критерии оценки

1. Наличие работоспособного прототипа — **40 баллов**.
2. Корректность структурирования базы знаний и качество ответов системы — **20 баллов**.
3. Качество выявления обращений для сотрудников различных линий поддержки, а также распознавания нецензурной лексики — **10 баллов**.
4. Корректность методики оценивания работы технических специалистов и качества донесения информации — **20 баллов**.
5. Интуитивность веб-интерфейса — **10 баллов**.
